# 期权持仓量官方汇总数据源 — 接口可行性验证

- 验证日期：2026-10-20
- 验证对象：用户提供的两个官方统计页
  - 上交所：<https://www.sse.com.cn/assortment/options/date/>
  - 深交所：<https://www.szse.cn/option/quotation/statistical/tabulate/index.html>
- 目的：判断能否用官方公开接口替代 / 校验 Tushare `opt_basic` + `opt_daily`

---

## 一、结论速览

| 用途 | 是否可行 | 结论 |
|---|---|---|
| 替代 `opt_basic` 拿**合约清单** | ✅ 可行 | 上交所云行情 6 次请求 / ~150 KB / ~2 秒拿全 684 个沪市合约；深交所合约清单接口未打通 |
| 替代 `opt_daily` 拿**合约级历史** | ❌ 不可行 | 官方只给标的级汇总，没有逐合约历史明细 |
| **标的级持仓量/成交量校验** | ✅ 强烈推荐 | 沪市与 Tushare **逐位完全相等**，可直接做每日勾稽 |
| 深交所**单边口径**数据直接替换 | ⚠️ 不可 | 口径不同（单边 vs 双边），差 7.7%~8.3%，需换算或只做参考 |

**核心发现：沪深两市统计口径不一致。**
- 上交所 `LEAVES_CALL_QTY` / `LEAVES_PUT_QTY` = 双边加总，与 Tushare `opt_daily` 的 sum(oi) **完全一致**。
- 深交所 `kzccsl` / `kdccsl` = **对冲后单边**，与 Tushare **系统性偏低 7.7%~8.3%**。
- 深交所报表页脚原文：「认购（认沽）未平仓量按对冲后的权利仓（或义务仓）单边计算。」

## 二、上交所：两个接口

### 2.1 合约清单（可替代 opt_basic）

官网期权行情页 `<https://www.sse.com.cn/assortment/options/price/>` 的真实后端是**云行情接口**，不是 `query.sse.com.cn`。

```
GET https://yunhq.sse.com.cn:32042/v1/sho/list/exchange/underlyingstock
        ?select=stockid
GET https://yunhq.sse.com.cn:32042/v1/sho/list/tstyle/{标的代码}
        ?select=contractid,last,volume,amount,open_interest
```

实测：

| 标的 | 合约数 | 其中认购/认沽 |
|---|---|---|
| 510050 上证50ETF华夏 | 102 | 51 / 51 |
| 510300 沪深300ETF华泰柏瑞 | 118 | 59 / 59 |
| 510500 中证500ETF南方 | 142 | 71 / 71 |
| 588000 科创50ETF华夏 | 162 | 81 / 81 |
| 588080 科创50ETF易方达 | 160 | 80 / 80 |
| **合计** | **684** | 342 / 342 |

返回样例（510050 前两条）：

```json
[["510050C2610M02650", 0.2219, 256, 544552, 133],
 ["510050C2610M02700", 0.173,  842, 1362465, 737]]
```
字段顺序：`[合约代码, 最新价, 成交量, 成交额, 持仓量]`。

**要点：**
- 合约代码是 `510050C2610M02650` 这种「标的+C/P+年月+M+行权价」格式，标的、认购认沽、到期月、行权价**全部可解析**，不需要再算 `opt_code ↔ ts_code` 映射。
- 端口 `:32041` 是 http，`:32042` 是 https，脚本里要写降级。
- 一次拉全 5 个标的只需 5 次请求，对比 `opt_basic` 现在是 3 次分页、13,124 行、约 7.5 MB。**数据量降到 1/50。**

### 2.2 每日统计（可做校验）

```
GET https://query.sse.com.cn/commonQuery.do
  ?sqlId=COMMON_SSE_ZQPZ_YSP_QQ_SJTJ_MRTJ_CX
  &isPagination=true
  &tradeDate=20261019
  &pageHelp.pageSize=10&pageHelp.pageNo=1
  &pageHelp.beginPage=1&pageHelp.cacheSize=1&pageHelp.endPage=1
```

参数注意：
- `tradeDate` 用 **`YYYYMMDD`**（`20261019`）；传 `2026-10-19` 会返回 0 行。
- 不传 `tradeDate` 默认返回当日。
- 历史可回溯：实测 2026-03-20、2026-06-15、2026-08-14、**2025-06-04** 均正常返回。

返回字段（每标的一行，共 5 行）：

| 字段 | 含义 | 与 Tushare 对应 |
|---|---|---|
| `SECURITY_CODE` | 标的代码 | — |
| `SECURITY_ABBR` | 标的名称 | — |
| `CONTRACT_VOLUME` | 上市合约数 | — |
| `CALL_VOLUME` / `PUT_VOLUME` | 认购/认沽成交量 | `c_vol` / `p_vol` |
| `TOTAL_VOLUME` / `TOTAL_MONEY` | 总成交量/成交额 | — |
| `LEAVES_CALL_QTY` / `LEAVES_PUT_QTY` | 未平仓认购/认沽 | `c_oi` / `p_oi` |
| `LEAVES_QTY` | 未平仓合计 | `c_oi + p_oi` |
| `CP_RATE` | 认沽/认购(%) | `oi_pcr × 100` |
| `TRADE_DATE` | 数据日期 | — |

**月度统计**：同端点，`sqlId=COMMON_SSE_ZQPZ_YSP_QQ_SJTJ_YDTJ_CX`，`tradeDate=202609`。

## 三、深交所：交易持仓汇总统计

### 3.1 接口

页面 `<https://www.szse.cn/option/quotation/statistical/tabulate/index.html>` 的报表目录号是 **`option_jycchztj`**（交易持仓汇总统计），不是 `ysp*` 系列（我之前按 `ysp*` 探测全部返回 0，走错了方向）。

```
GET https://www.szse.cn/api/report/ShowReport/data
  ?SHOWTYPE=JSON
  &CATALOGID=option_jycchztj
  &TABKEY=tab1
  &PAGENO=1
  &PAGESIZE=50
  &txtSearchDate=2026-10-19        # 注意是 YYYY-MM-DD
```

参数行为：
- 传 `txtSearchDate` → 精确返回该日 4 行（深市 4 个标的）。
- 不传 → 返回**全部历史**，共 4,558 行 / 228 页（每页 20 行）。用 `PAGESIZE=500` 分页拉全。
- `PAGESIZE` 超过 500 时会被强制截断，实际单页最多 500 行。
- 实测全量跨度：2025-12-25 ~ 2026-10-20（195 个交易日）。

### 3.2 字段

| 字段 | 含义 | 关系 |
|---|---|---|
| `jyrq` | 交易日期 | `YYYY-MM-DD` |
| `bdzqdm` | 标的代码+名称 | `创业板ETF易方达(159915)` |
| `kzjysl` | 认购交易数量 | **= Tushare `c_vol`**（逐位相等） |
| `kdjysl` | 认沽交易数量 | **= Tushare `p_vol`**（逐位相等） |
| `kzkdjybl` | 认购/认沽交易比(%) | `kdjysl / kzjysl × 100` |
| `kzccsl` | 认购持仓数量 | ⚠️ **单边**，非 Tushare `c_oi` |
| `kdccsl` | 认沽持仓数量 | ⚠️ **单边**，非 Tushare `p_oi` |
| `kzkdccbl` | 认购/认沽持仓比(%) | `kdccsl / kzccsl × 100`（东财接口 `rcrpccb` 同值） |

**页脚原文注释（metadata.footer）：**
> 注：1、认购（认沽）期权成交量是按买入（或卖出）单边计算。
> 　　2、认购（认沽）未平仓量按对冲后的权利仓（或义务仓）单边计算。

### 3.3 成交量：逐位相等 ✅

| 日期 | 深交所 kzjysl | kdjysl | Tushare c_vol | p_vol | 结果 |
|---|---|---|---|---|---|
| 2026-10-19 | 1,178,601 | 878,515 | 1,178,601 | 878,515 | 全等 |
| 2026-10-16 | 1,544,013 | 975,842 | 1,544,013 | 975,842 | 全等 |
| 2026-10-15 | 1,587,027 | 1,114,869 | 1,587,027 | 1,114,869 | 全等 |

成交量口径完全一致，可以直接替换使用。

### 3.4 持仓量：系统性偏低 ⚠️

| 日期 | 深交所 单边持仓C | Tushare 双边 c_oi | 比值 | 深交所 单边持仓P | Tushare p_oi | 比值 |
|---|---|---|---|---|---|---|
| 2026-10-15 | 1,351,326 | 1,479,025 | 0.9137 | 581,747 | 695,031 | 0.8370 |
| 2026-10-16 | 1,378,705 | 1,503,708 | 0.9169 | 608,589 | 716,075 | 0.8499 |
| 2026-10-19 | 1,433,529 | 1,553,028 | 0.9231 | 624,815 | 713,188 | 0.8761 |

- 认购端差 7.7%~8.6%，认沽端差 12.4%~16.3%，**认沽端偏离更大**。
- 单边 + 成交量 ≠ 双边（实测 10-19：1,433,529 + 1,178,601 = 2,612,130 ≠ 1,553,028），说明这不是简单的「除以 2」换算。
- **结论：深交所的单边持仓无法可靠还原成双边持仓，不能直接替换 Tushare 的 `oi`。**

### 3.5 PCR 影响

| 日期 | 深交所单边口径 PCR | Tushare 双边口径 PCR | 偏差 |
|---|---|---|---|
| 2026-10-13 | 0.5011 | 0.5331 | -6.0% |
| 2026-10-14 | 0.4834 | 0.5149 | -6.1% |
| 2026-10-15 | 0.4305 | 0.4699 | -8.4% |
| 2026-10-16 | 0.4414 | 0.4762 | -7.3% |
| 2026-10-19 | 0.4359 | 0.4592 | -5.1% |

深交所口径的 PCR **系统性偏低 5%~8%**，如果和历史序列（Tushare 双边口径）混用，会造成明显的断点。**只能用来看方向，不能并入现有时间序列。**

## 四、建议的落地方案

按「收益 / 风险」排序：

### P0 · 用沪市官方数据做每日勾稽（推荐先做）

在 `fetch2b.py` 生成 `pcr_raw.csv` 后，加一步校验：
1. 调上交所 `COMMON_SSE_ZQPZ_YSP_QQ_SJTJ_MRTJ_CX` 取当日 4 个沪市标的汇总。
2. 与 `pcr_raw.csv` 当日的 `c_oi / p_oi / c_vol / p_vol` 逐字段比对。
3. 偏差 > 0.5% 时打印告警（不中断管线），并把偏差写进报告附录。

**价值：** 彻底堵住「合约缓存过期导致 PCR 静默漏算」这个已存在的老问题——不用改 TTL，也能每天自动发现漏算。成本 1 次请求。

### P1 · 合约清单换源（可选）

把 `opt_basic` 的合约映射换成上交所云行情：
- 沪市：`/v1/sho/list/tstyle/{510050,510300,510500,588000,588080}`，5 次请求。
- 深市：官方合约清单接口未打通，保留 Tushare。

**收益：** `opt_contracts.json` 的 TTL 问题直接消失（每天都能拿到最新在市合约），传输量从 7.5 MB 降到 150 KB。
**风险：** 私有接口无 SLA；沪深两套逻辑并存，复杂度上升。建议先做 P0 验证稳定性，观察 2~4 周再决定。

### P2 · 深交所数据仅作参考

`option_jycchztj` 的单边持仓只写进报告附录作为「交易所单边口径」参考，**不并入 PCR 主序列**。成交量字段可以并入（口径一致）。

## 五、风险与运维提示

1. **两个接口都是官网页面背后的私有接口**，没有公开文档和 SLA，字段名/路径随时可能变。必须在代码里用 try/except 包住，失败只告警不中断。
2. **上交所云行情双端口**：`https://yunhq.sse.com.cn:32042`（https）、`http://yunhq.sse.com.cn:32041`（http），需写降级。
3. **日期格式不统一**：上交所 `tradeDate=20261019`，深交所 `txtSearchDate=2026-10-19`，容易踩坑。
4. **深交所分页**：`PAGESIZE` 上限 500，全量拉取需 10 页；按日拉取则 1 页 4 行，推荐按日增量。
5. **当日数据可能未结算**：实测 10-19 盘后拉取上交所 510050 有 862 张差异。校验应针对**上一交易日**而非当日，或对当日结果放宽阈值。
