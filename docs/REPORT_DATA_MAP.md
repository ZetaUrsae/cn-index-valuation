# 报告数据地图（REPORT DATA MAP）

**这份文档回答一个问题：报告的每一部分、每一个数字，是从哪里来的。**

按报告章节顺序逐节列清：内容 → 中间文件 → 生成脚本 → 原始数据源（含接口）。  
配套文档：[DATA_SOURCES.md](DATA_SOURCES.md) 讲数据源本身的接口/单位/坑，  
本文档讲**报告内容与数据源的对应关系**。两份各查一半。

- 报告：`reports/index_val_report_<ASOF>.html`（模板 `scripts/template2.html`）
- 组装：`scripts/gen2.py`（读全部中间文件 → 组成 `work/data2.json` 的 `DATA` → 注入模板）
- 入口：`run_daily.py`（v2 管线，全程零 Tushare；Tushare 默认禁用）

## 一、取数层（run_daily.py 的 5 个同步步骤）

`run_daily.py` 依次执行 5 个同步步骤：**① 指数行情 → ② 指数估值 → ③ 期权 PCR →
④ ETF 份额与行情 → ⑤ 10Y 国债尾部补齐（非致命）**，
其后还有一个**补步骤：指数收盘价历史增量（非致命，东财 K 线，`fetch_close_hist.py`）**。

每个域的**优先级链、日常实际源、历史下界、Tushare 参与度**，唯一权威表在
[DATA_SOURCES.md](DATA_SOURCES.md) 第一节「总览」，此处不重复。
每次运行"实际用了哪个源"记录在 `work/provenance.json`（`provider` + `fallback_from` 字段）。

## 二、逐章节数据字典

### 0. 核心指标速览

- **字段**：`rows[]` 里的 close / pe_ttm / pe(静态) / pb / pe_pct / pb_pct / st(估值状态标签)。
- **中间文件**：`work/metrics.json`（键 = `000300.SH` 等 5 个 ts_code）。
- **脚本**：`scripts/process.py`。
- **计算链**：`data/raw.json` 的 `basic` 段（最新一行）+ `daily` 段。
- **分位口径**：**近 10 年**日频 PE(TTM)/PB 的百分位（`pctile`，只用正值样本）；  
  5 年分位也在 metrics.json 里（`pe_ttm_pct_5y`），报告表格当前用 10 年口径。
- **来源**：`basic` 段 = 东财 `RPT_INDEX_COMPONENT`（成分股，缓存 7 天）
  - `RPT_VALUEANALYSIS_DET`（全市场估值，单次 pageSize=6000），  
    按 `PE=Σmv/Σ(mv/PE_i)`（总市值加权、含亏损股）聚合，与 Tushare 存值误差 0.17%。

### 一、基本面：估值分析

**① 估值总表**（每指数一行）

| 列              | 字段                         | 出处                                                                   |
| -------------- | -------------------------- | -------------------------------------------------------------------- |
| 收盘/涨跌          | `close`, `ytd`, `m1`, `y1` | metrics.json（close 来自新浪日线；区间涨跌按日线算）                                  |
| PE-TTM/静态PE/PB | `pe_ttm`, `pe`, `pb`       | metrics.json ← 东财聚合（静态 PE 用 `PE_LAR`）                                |
| 10年分位          | `pe_pct`, `pb_pct`         | process.py 对 raw.json `basic` 全史计算                                   |
| 点位分位/点位中位数        | `close_pct`, `close_med`   | process.py 对 `data/close_history.json` 近10年日频收盘价计算（v2.6.3，与 PE/PB 分位同式；科创50 自 2020-07 上市起）。不进信号矩阵、不参与估值状态色标；表下小字展示沪深300/中证500/创业板指近十年点位中位数 |
| PE 区间统计        | `pe_min/med/max`           | 同上                                                                   |
| 总市值            | `mv`（万亿）                   | 东财 `TOTAL_MARKET_CAP`（单位=元，直存不换算）                                    |
| 隐含 ROE         | `roe`                      | = PB / PE(TTM)，process.py                                            |

**② PE/PB Band（估值带，v2.5.9 起取代旧"估值中枢迁移"月度折线）**

- Wind 式估值带：收盘价折线 + 窗口内 PE(TTM)/PB 的均值 ±1σ/±2σ × 当期
  EPS(TTM)（=收盘价/PE）/ BPS（=收盘价/PB），通道随盈利披露逐周倾斜。
- `gen2.py` 的 `band_data()`：每 ISO 周取最后一个交易日（周采样，10 年约 521 点/指数），
  注入 `DATA.band`（`{指数: {dates, close, pe, pb}}`）；
  统计与画线在前端完成。
- **收盘价**：`data/close_history.json`（2015~2019 段 Tushare `index_daily`
  一次性回填（2026-10-21，仅此一次），其后东财 K 线增量；科创50 自 2020-07-24）。
- **交互**：默认沪深300 / 5 年窗口 / PE Band；指数（5 个）、窗口（3/5/10 年）、
  指标（PE/PB）三组按钮切换；窗口数据不足 80%（如科创50 × 10 年）自动回退
  "上市以来"并在图下注明。

**③ ERP（股债性价比）子章节** —— 交互式走势图 + 联动读数条（v2.6.1 起）

- `ERP = 100/PE(TTM) − 10Y 国债收益率`，`gen2.py` 内计算；
  10Y 序列来自 `data/yield10y_history.json`（东财 `RPTA_WEB_TREASURYYIELD`，
  数据源中国债券信息网/中债，2002-01-04 起日频）；
- **图与读数条共用一套状态（v2.6.1）**：`erp_weekly()` 注入 `DATA.erpS`
  （每 ISO 周取最后交易日，五指数各约 604 点），前端 `erpSlice()` 按所选
  **指数（5 个，默认沪深300）× 窗口（2015以来/10/5/3 年，默认 2015以来）**
  切片并计算均值 ±1σ/分位——图、读数条、"怎么看"说明三者同步切换；
  关键极值圆点（股灾前顶/2019底/疫情底/牛市顶/十年最高）仅沪深300 显示。
  y 轴自适应（创业板指/科创50 的 ERP 可为负）；
- **口径注意**：读数条是**所选窗口的周频口径**（与图一致），不再是固定
  "沪深300·2015以来日频"——±1σ 触发线随窗口变化，跨窗口比较不成立，
  报告图下说明已注明；v2.6.1 起 `DATA.erp`（日频统计块）已从 gen2 删除。
- **版式（v2.4.0 起）**：折线图上方不再放"当前读数表 + 怎么看"两栏卡片；
  图下方一张卡里是**横向读数条**（6 格，从左到右：当前 ERP / 历史分位 / 均值±1σ /
  +1σ 触发线 / −1σ 触发线 / 距 +1σ），再接一段合并后的说明
  （怎么看 + 触发条件 + 低利率口径提醒 + 样本区间与局限）。

### 二、资金面：ETF 份额变化

- **字段**：`fund.{d5,d20,d60,ytd,…}`（绝对增亿份）与 `*p`（百分比）、`hi/lo`（历史极值）、信号标签。
- **中间文件**：`work/shares.json`（proc2.py 产出），底层是 `data/etf_raw.json` 的 `shares` 段。
- **来源**：
  - 沪市 ETF（510050/510300/510500/588000）：上交所 `COMMON_SSE_ZQPZ_ETFZL_XXPL_ETFGM_SEARCH_L`，
    按 `STAT_DATE` 取当日全市场名单（**不是全历史**，一次只给一日，可回查任意历史日期）；
  - 深市 159915：深交所 `CATALOGID=1105&txtkey1=159915` 当日快照（`dqgm` 万份）；
    **只有当日一行**，靠每日运行追赶；漏掉的日子由深交所「基金规模」区间报表
    （`CATALOGID=scsj_fund_jjgm`，一次可查 6 个月）自动回补，**不需要 Tushare**；
    沪市漏日由管线按 `STAT_DATE` 逐日回查补齐；两市都不需要人工干预；
  - ETF 现价：新浪行情。
- **坑**：深交所快照取值日一律用 `min(metadata.subname, end)`，列头括号印的是前一天会误导；  
  晚间值是参考值、T+1 早间定稿（06:00 定时任务天然拿确认值）。
- **份额走势图**（v2.5.9 起为该章唯一图表，通栏全宽；原"份额变化（亿份）"柱状图已删）：
  v2.6.2 起窗口可切换（**全部 / 近三年 / 近一年，默认近一年**）。`gen2.py` 注入
  `DATA.shareAll`（etf_raw.json 份额日频每 2 日抽 1 点、锚定最新日，约 461 点/ETF，
  2023-01 起，日期为 YYMMDD 整数），前端按点数切片（125=近一年、375=近三年、0=全部）、
  起点＝窗口内首个有效值重新定基＝100。

### 三、情绪面：期权持仓 PCR

- **字段**：`pcr.{oi(当日), oi_pct(样本分位), oi_med/min/max/ma20/p25, vol(成交量PCR), n, start, series}`。
- **PCR 走势图**（v2.6.2 起）：窗口可切换（**全部 / 近三年 / 近一年，默认近一年**）。
  `gen2.py` 注入 `DATA.pcrAll`（pcr_raw.csv 每 2 日抽 1 点、锚定最新日，约 489 点，
  2022-10-10 起，以沪深300 标的日期对齐、缺日为 null，科创50 自 2023-06 由
  connectNulls 处理）。**表格与信号矩阵的 PCR 历史分位固定按全样本计算，不随窗口联动**
 （分位是信号输入，避免图表与表格口径打架）。
- **中间文件**：`work/pcr.json`（proc2.py），底层 `data/pcr_raw.csv`（逐日原始）+ `work/opts.json`（合约表）。
- **来源**：交易所官方期权日报
  - 上交所：`query.sse.com.cn COMMON_SSE_ZQPZ_YSP_QQ_SJTJ_MRTJ_CX`（需 Referer）；
  - 深交所：期权日统计接口（同 Host，注意限流）；
  - 回溯窗口：库里最后一天前 1 天 ~ asof（日常 1~2 发，覆盖缺日与定稿修正）。
- **口径**：PCR = 认沽持仓量 / 认购持仓量，按各指数**主要 ETF 期权**逐日汇总；  
  样本自 2022-10-10（科创50 自 2023-06-05）。
- **两市持仓量口径不同**（v2.5.0）：沪市 `LEAVES_*_QTY` 为双边加总；深市 `kzccsl`/`kdccsl` 为
  对冲后单边，**直接落库原值、不做换算**（与深交所页面逐位一致）。2026-09-09 起为单边、
  更早为 Tushare 双边，创业板指 PCR 历史分位跨该断点，页面已注明。
- **已知口径差**：到期日（周三）交易所报结算后持仓、Tushare 报收盘持仓，  
  `KNOWN_OI_DIVERGENCE` 已在 `ivdata/providers/exchange.py` 记录离群日。

### 四、技术面：K 线形态与均线

- **字段**：`tech.{pct, ma5/20/60/120/250, above_ma20, ret5/20, vol/v20, dd_from_250high, hi250, lo250, …}` + 60 日 K 线序列。
- **中间文件**：`work/tech.json`（tech.py，读 raw.json `daily`）；  
  K 线扩展（含影线比例等）由 `prep.py` 追加（纯本地计算，零外部请求）。
- **来源**：新浪 `CN_MarketData.getKLineData`（分页 1023 根；vol 单位股 → 除以 100 成手）。

### 五、四维信号矩阵

- 纯 `gen2.py` 的四个 signal 函数对上述四维数据分层打标签：  
  `status()`（估值分位五档）、`signal_fund()`（60 日份额变化率五档）、  
  `signal_pcr()`（PCR 分位五档）、`signal_tech()`（相对 MA20 位置五档）。
- 无新增数据源。

### 总结

- `gen2.py` 里的 `summary_html`：**按当日数据实时排序生成**（PE 分位排序、PB 分位最低、  
  隐含 ROE 最高、60 日资金、PCR 分位、250 日回撤），不是人工文本，不会过期。

### 机构展望（views）/ 综合解读（syn）

- 存放：`data/manual_inputs.json` 的 `views` / `syn`。
- **`views` 按机构组织，一行一家**：`{"org": 机构名, "date": 发布日, "scope": 覆盖标的, "view": 观点文本}`。
  报告渲染成「机构 / 发布日 / 覆盖标的 / 核心观点 / 对照读数」五列；
  **对照读数由 `gen2.py` 按当日 `rows` 自动生成**（PE-TTM × 分位、份额 60 日变化），
  观点文本里不要再手写一遍指标数字，避免两处不一致。
- **覆盖范围**：只收录**外资投行**（高盛、摩根士丹利、摩根大通、瑞银、野村、花旗、美银、德银等）
  对 **沪深300 / 创业板指 / A股整体** 的公开观点；不逐指数铺开，也不收内资券商。
- `syn[指数]` 是一句话结论，落在五、信号矩阵末列（目前只写沪深300、创业板指）。
- **生成方式**：每日流程在管线跑完后，**读 `work/metrics.json`、`pcr.json`、`shares.json` 据实撰写，
  回写 `manual_inputs.json`，再只重跑 `gen2.py`**（定时任务第 3 步）。
- `views` 为 `[]` 时表格显示"本期未收录外资投行观点"，不报错。
- **本文件不含任何数值指标**：行情、PE/PB、PCR、份额、10Y 全部由管线自动写入 `data/` 历史库。
- 股息率已于 v2.4.0 从报告移除（中证 `data-service/indexValuation` 只覆盖 8 只指数且有当日快照，
  创业板指/科创50 无来源），原因与接口明细见 RUNBOOK 7.3。

## 四、怎么核对某个数字

1. **先看溯源**：`work/provenance.json` 里该域当次实际用的 provider；
2. **对中间文件**：按〇节速查表找到对应 work/*.json，确认报告值 == 中间值（排除 gen2 组装错误）；
3. **对原始源**：按 DATA_SOURCES.md 的接口重发一次请求比对；
4. **交叉校验工具**：
   ```bash
   python tools/verify_sources.py --asof YYYYMMDD --csv   # 估值/行情/PCR 多源对照
   python tools/compare_tushare_2026.py                    # 2026 全年东财 vs Tushare 存值（只读）
   ```
5. **第三方官方对照基准**（2026-10-21 实测口径）：
   - 中证指数官网 `indexCsiDsPe`：仅 300/50 的静态 PE（字段名叫 peg），±3% 容差；
   - 国证官网 `GET www.cnindex.com.cn/index/indexList?channelCode=-1&rows=2000&pageNum=1`：  
     覆盖创业板指 399006 的 peStatic/peDynamic/pb **当日快照**。PB 与我们差 0.21%（一致✓）；  
     PE 低 ~15% 是编制方加权口径差（自由流通分级靠档 vs 我们总市值加权），**不可直接对比 PE**；  
     无历史序列，只能做当日校验。

## 五、报告版式与口径约定

改版式请改 `scripts/template2.html`（唯一模板），不要手改报告。

1. **章节顺序**（用户指定，勿改）：核心指标速览 → 一、基本面 → 二、资金面 →
   三、情绪面 → 四、技术面 → 五、四维信号矩阵 → 总结。总结收尾，
   不要在开头再放结论卡。附录（标的对照）已于 v2.4.1 删除。
2. **配色**：涨跌遵循 A 股惯例**红涨绿跌**；估值/信号标签用
   "绿＝有利、红＝不利"的温度色阶。
3. **数据日期各自标注、不写死差异**：10Y `bonddate`、行情 `stats_to`、ERP `stats_to`
   各自显示自己的日期，**不要新增"相差 N 个交易日"这类固定差值文案**。
