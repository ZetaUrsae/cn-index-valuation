## 二、各源详解

### 1. 东方财富 —— 估值（核心）

**接口**：`https://datacenter-web.eastmoney.com/api/data/v1/get`

整个估值链路分两步：

1. **取成分股**：报表 `RPT_INDEX_COMPONENT`
   ```
   reportName=RPT_INDEX_COMPONENT&filter=(INDEX_CODE=000300)&pageSize=500
   ```
   - ⚠ `filter` 里**必须用裸值**（`(INDEX_CODE=000300)`）。加引号会触发 antlr
     `InputMismatchException`，因为该列是数值型。
   - 实测返回真实成分：沪深300 恰好 300 只、科创50 恰好 50 只、创业板指 100 只。
   - 缓存 7 天（`data/em_constituents.json`）。成分调整是半年级别的，7 天足够。

2. **取全市场估值**：报表 `RPT_VALUEANALYSIS_DET`
   ```
   reportName=RPT_VALUEANALYSIS_DET&source=WEB&client=WEB
   &filter=(TRADE_DATE='2026-10-19')&pageSize=6000
   ```
   - ⚠ `source=WEB&client=WEB` **必填**，缺了会被拒。
   - `pageSize=6000` 一次拿回全部 5575 只股票，**单次请求**搞定全市场。
   - 日期过滤要用**单引号**（`TRADE_DATE='2026-10-19'`，连字符格式）。

**聚合口径（关键，误差 0.17%）**

```
PE = Σmv / Σ(mv / PE_i)      PB = Σmv / Σ(mv / PB_i)
权重 = TOTAL_MARKET_CAP（总市值），不是流通市值
亏损股（PE ≤ 0）必须计入，不能剔除
```

这个口径与中证指数公司的计算方式一致。踩过的坑：

| 尝试 | 沪深300 PE 误差 |
|------|-----------------|
| 流通市值加权、剔除亏损 | ≈ 5% |
| 总市值加权、剔除亏损 | ≈ 15% |
| **总市值加权、含亏损** | **0.17%** ✅ |

**字段对照**

| 报告字段 | 东财字段 | 说明 |
|----------|----------|------|
| `pe_ttm` | `PE_TTM` | 动态市盈率 |
| `pb` | `PB_MRQ` | 市净率（最近报告期） |
| `pe`（静态） | `PE_LAR` | 最近年报 PE，聚合后与库内历史 `pe` 逐位吻合（192.2792 vs 192.2791） |
| `total_mv` | `TOTAL_MARKET_CAP` | **单位是元**，数值与库内历史存值完全相等，**不要任何换算** |
| `float_mv` | `NOTLIMITED_MARKETCAP_A` | 自由流通市值 |
| `turnover_rate_f` | 需另算 | 由成交量与自由流通股本推导 |

> 单位坑：曾错误地除以 1e4（以为元→万元），导致 `total_mv` 差 10000 倍
> （6551594005 vs 65515922156051）。**东财的元数值直接就是历史库存的值**，
> 与常见接口文档标注的"万元"口径不同。

**历史下界**：`2018-01-02`。2017-12-01 及更早返回"返回数据为空"。

**已知偏差**：东财回补历史时用的是**当前成分股**，所以越往前偏离越大：

| 日期 | 沪深300 PE / PB 偏差 |
|------|----------------------|
| 2019-01-02 | +0.11% / −2.27% |
| 2021-01-04 | +6.95% / −0.73% |
| 2023-01-03 | −2.74% / −4.96% |

这正是历史段必须一次性写定的理由（东财不能用当前成分股回补早年），
写定后冻结、不再重拉；日常增量交给东财。

### 2. 新浪财经 —— 指数/ETF 行情

`https://money.finance.sina.com.cn/quotes_service/api/json_v2.php/CN_MarketData.getKLineData`

- 单次最多 1023 根 K 线，需分页。
- ⚠ `volume` 单位是**股**，历史库口径是**手**（1 手 = 100 股）→ **除以 100**。
- 无 `amount` 字段，按 `close × vol(手) × 100 / 1000` 估算（千元）。
- 返回体可能是 JSONP，`ivdata.http._loads` 已做 BOM/JSONP 容错。

### 3. 上海证券交易所

**期权日统计**
`http://query.sse.com.cn/commonQuery.do?sqlId=COMMON_SSE_ZQPZ_YSP_QQ_SJTJ_MRTJ_CX&tradeDate=YYYYMMDD`

- 按 `tradeDate` 逐日查；每交易日 5 行（认购/认沽 × 持仓/成交）。
- 需要 `Referer: http://www.sse.com.cn/`。
- 已实现 `pageHelp.pageSize=100` 分页循环，实测只有 5 行，但保留以防改版。
- ⚠ **到期日（周三）差异**：交易所报的是**结算后**持仓量，与**收盘**持仓量口径不同。
  2026-09-23 实测 `oi_pcr` 差到 0.577×（成交量、成交额完全一致）。
  这是会计口径差异，不是取数 bug，已在 `exchange.py` 记录为
  `KNOWN_OI_DIVERGENCE = ("20260923",)`。

**ETF 份额**

```
GET https://query.sse.com.cn/commonQuery.do
    ?sqlId=COMMON_SSE_ZQPZ_ETFZL_XXPL_ETFGM_SEARCH_L
    &isPagination=true&pageHelp.pageSize=500&pageHelp.pageNo=1
    [&STAT_DATE=2026-10-20]        ← 可选；不传则返回「最新一日」
```

- 一次返回**某一日全市场 ETF 名单**（约 920 只 / 2 页），字段 `SEC_CODE` + `TOT_VOL`（万份，
  与库内历史份额字段同值）；
- **没有区间参数**。`STAT_DATE` 是唯一的时间入口：传某个历史日期可回查当日的份额，
  实测 `STAT_DATE=2026-09-15` 返回 907 行、值与我们库里逐位一致；
- 因此 provider 按 `STAT_DATE=end` 精确定位当日，取不到再退回「最新一日」——
  这样补跑历史日期（`--asof`）也不会拿错日子；
- **按日缓存**：四只沪市 ETF 共用同一份名单，不缓存就要把同一张表拉 4 遍（每遍 2 页）。
- 漏日同样能自愈：`Pipeline._fill_share_gaps` 检测到缺口后按日逐个回查（缺口通常 1~2 天），
  只补缺失日期，当天（未定稿）一律留给明天。

**交易日历**
中证指数官网 `index-perf-tradeDate`，一次返回全序列（很小），provider 内做了进程内缓存，
一次运行只拉 1 次。

### 4. 深圳证券交易所 —— 深市 ETF 份额

`GET https://www.szse.cn/api/report/ShowReport/data`
`?SHOWTYPE=JSON&CATALOGID=1105&TABKEY=tab1&PAGENO=1&txtkey1=159915`

`CATALOGID=1105` 是「基金列表」，约 1075 只基金 / 54 页。页面上的「代码或简称」
筛选框就是 `txtkey1`，实测能把结果缩到 1 行，**一次请求即可**，
不必再像早期实现那样翻 54 页（翻页正是触发限流的主因）。

字段 `dqgm` = 当前规模（万份），与库内历史份额字段**逐位一致**：
2026-10-20 实测深交所 2,673,645.49 vs 库内存值 2,673,645.4936，只差深交所保留 2 位小数。

四个必须记住的性质：

1. **快照只有当日一个值，没有历史区间参数。** 每次只贡献 1 行，靠每日运行往后追；
   漏跑的日子由下面的「区间报表」（`scsj_fund_jjgm`）自动回补。
2. **日期归属容易错位一天。** `metadata.subname` 是快照日（形如 `2026-10-20`），
   而列头括号里印的日期却是前一天。实测 `dqgm` 的值属于 `subname` 那天，
   所以取 `min(subname, end)`：早间运行时 subname 可能已翻到下一交易日，
   但值仍是 end 日的确认值，钳到 end 才正确。
3. **晚间值是临时值。** 页面原文：「该字段 T 日晚间更新的 T 日规模仅供参考，
   以 T+1 日早间更新的 T 日规模为准」。定时任务 06:00 跑，天然拿到确认值。
4. **限流是按主机、按「短时间总请求数」的，不是 QPS 限流。** 同一 IP 短时间内
   连发十几请求就会被 WAF 掐断，表现为 `RemoteDisconnected`：TCP 能连、TLS 能握手，
   但 HTTP 请求直接被丢弃，**连首页都打不开**，实测封禁可达 1 小时以上。
   因此要两手抓：`ivdata/config.py` 把 `www.szse.cn` 的 QPS 压到 1（`HOST_QPS`），
   更重要的是**少发请求**——`Pipeline.sync_pcr` 的回溯窗口已收到
   「库里最后一天的前 1 天 ~ asof」：日常只缺 1 天新数据，所以通常只发 1~2 发
   （曾因 40 天窗口每次运行发 26 发，把配额吃光）。
   另外 `Pipeline.sync_etfs` 有「疑似未刷新就换源重取」的判定。

**为什么每日取而非周度顶替**：份额是日报「资金面」的 5/20/60 日变化基准，
周内不动就会让曲线出现台阶，所以仍然每日从深交所取。

**深市份额的缺口回补（区间报表）**

`CATALOGID=scsj_fund_jjgm`（页面上是「基金规模」查询页，可选时间窗口）：

```
GET https://www.szse.cn/api/report/ShowReport/data
    ?SHOWTYPE=JSON&CATALOGID=scsj_fund_jjgm&jjlb=ETF
    &txtDm=159915&txtStart=2026-04-21&txtEnd=2026-10-21&PAGENO=1
```

- 页面查询条件在接口元数据里写死 `dateRange('all','${txtEnd}','6m')`：**单次最多 6 个月**，
  每页 20 行，字段 `size_date` / `current_size`（万份，含千分位），
  与库内历史份额字段同源同值；
- **标签日错位一个交易日**：`size_date` 标的是「官方份额日的前一个交易日」，即
  `row[label] == 官方[交易日历中 label 的下一个交易日]`。两个独立窗口实测
  155/155 行全部命中（2026 年 4-10 月 118 行、2-4 月 37 行），只有末尾未定稿的
  1~2 行例外。换算必须走交易日历取「下一个交易日」，不能简单 +1 天；
- **末尾 1~2 行未定稿**（T 晚间临时值、T+1 早间为准），provider 直接丢弃
  「官方日 > 今天-1」的行——这几天正好由每日快照覆盖；
- 成本：管线**只在检测到缺口时**才调用，45 天缺口 ≈ 2 页 = 2 个请求，
  正常每天跑一次则一次都不发；缺口超过 120 天（首次建库 / 长期停机）时只补最近
  120 天，更早的不自动回补，避免一次翻几十页把配额打光。

> 管道分工：`SzseEtfShare` 负责当日快照，`SzseEtfShareRange` 负责历史缺口，
> 回补只写缺失日期、已有日期一律以库内为准（标签错位一旦写反会污染整条序列）。

### 5. 中证指数官网（仅交叉校验）

`https://www.csindex.com.cn/csindex-home/perf/indexCsiDsPe`

三个致命问题，导致**不可作为主源**：

1. 返回字段名叫 `peg`，实际是**静态 PE**（不是 PEG，也不是 TTM）；
2. 没有 PB；
3. 不覆盖创业板指。

因此只用于「数量级 sanity check」：沪深300/上证50 的静态 PE 与 TTM PE 接近，
可以用 ±3% 判；中证500/科创50 天然偏离 20%~45%（成长股盈利波动大），不判。

历史版本曾以某收费数据源作兜底与历史校准，现已整体移除（代码、配置、文档均不再保留入口）。

## 四、精度验证记录

### 估值复现（2026-10-19）

| 指数 | PE 偏差 | PB 偏差 |
|------|---------|---------|
| 沪深300 | −0.24% | −0.47% |
| 上证50 | −0.26% | −0.57% |
| 中证500 | +0.35% | −0.04% |
| 创业板指 | +0.02% | **+2.55%** |
| 科创50 | +0.00% | **+2.81%** |

`total_mv` 吻合到 0.00003%。深市两个指数的 PB 偏差 2.5%~2.8%，
怀疑与深市自由流通市值口径差异有关，尚在观察。

### 深市期权未平仓量：直接用页面单边原值（v2.5.0 起）

深交所「交易持仓汇总统计」页面（`CATALOGID=option_jycchztj`）披露的未平仓量，页脚注明为
**对冲后单边**（`kzccsl` / `kdccsl`）；而上交所日统计（`LEAVES_CALL_QTY` / `LEAVES_PUT_QTY`）
库内 2026-09-08 前的历史值均为**双边加总**口径。两市定义不同，数值不可直接互比。

**现行做法（2026-10-21 起）**：深市持仓量**直接落库页面原值，不做任何换算**，
报告里创业板指的持仓量、PCR 与深交所官网页面逐位对得上，便于人工复核。

- 交易日 2026-09-09 起的深市行已按此还原（72 行，3 个深市标的），
  校验：159915 `2026-10-20` → 1,444,503 / 643,044，PCR 0.4452，与页面「认沽认购未平仓比率 44.52%」一致。
- 2026-09-08 及更早：双边口径原值（历史不改）。
- **已知断点**：2026-09-08 → 09-09 之间深市持仓量约有 −5%~−8% 的台阶，
  创业板指 PCR 历史分位**跨越该断点**，仅作相对参照。报告页脚与情绪面注释已注明。

**已废弃做法（v2.4.x，勿恢复）**：曾把深市单边乘以固定系数 `(1.0868, 1.1566)` 换算回双边。
问题是该比值本身漂移，实测：

| 日期 | 页面单边 认购/认沽 | 当时库内（换算值） | 实测比值 c / p |
|---|---|---|---|
| 2024-09-20 | 878,610 / 498,223 | 909,608 / 532,534 | 1.0353 / 1.0689 |
| 2025-09-22 | 817,656 / 1,133,523 | 920,816 / 1,260,125 | 1.1262 / 1.1117 |

即真实比值在 1.03~1.13 间漂移，固定常数带来 ±4% 持仓量误差、PCR 2~4pp 误差；
且该做法使 2026-09-09~10-20 的行既非历史双边原值、也非官方页面值（第三种口径），
故整体撤回。成交量（`kzjysl`/`kdjysl`）两市定义一致，与页面逐位相同，从未受影响。

### 期权 PCR（2022-10 至 2026-10，4720 个共同行）

平均偏差 **0.03%**，唯一离群点是到期日 2026-09-23（口径差异，见上文）。

- **覆盖只有 8 只**：上证指数、上证180、上证50、沪深300、上证380、红利指数、中证红利、中证500；
  **没有创业板指、没有科创50**；
- **只有当日快照**：接受 `?tradeDate=` / `?indexCode=` 也不改变返回（仍是当天 8 只）；
- 与报告口径对照（2026-10-20）：上证50 `dp` 3.21%、沪深300 2.80%、中证500 1.51%。

结论：**不接入**。五只标的里两只无来源，做不成一列；2026-10-21（v2.4.0）已把股息率从报告移除。
其余探测过的端点（`perf/indexCsiDsPe` 只给 PE、`indexInfo/index-details-data` 500、
`exportExcel/downloadindex-perf` 需 POST、国证 `index/indexList` / `selectIndexByCode` 无股息率字段）
均不可用。

## 五、如何做交叉校验

```bash
# 全量校验（估值 + 行情 + PCR）
python tools/verify_sources.py --asof 20261019

# 只看估值
python tools/verify_sources.py --only valuation

# 导出明细 CSV 到 work/
python tools/verify_sources.py --csv
```

判读规则：

| 域 | 对照源 | 容差 | 含义 |
|----|--------|------|------|
| `valuation` | 前一日值 | ±15% | 单日跳变，超了基本是取数出错 |
| `valuation` | 中证静态 PE | ±3%（仅沪深300/上证50） | 数量级 sanity check |
| `quote` | 东财（仅当日） | ±0.2% | 两个独立源应当逐位相同 |
| `option_pcr` | 库内同日 / 前一日存值 | ±10% | 允许到期日口径差异 |

> ⚠ 校验时**不要拿 raw.json 当日的值做参照**——那本来就是主源写的，
> 会得到一个恒为 0.00% 的无意义自比。这是本工具最初版本的 bug。

## 六、新增数据源的检查清单

想接入新源，按这个顺序做，别跳步：

1. 手工 curl 一次目标接口，确认返回结构、单位、日期格式；
2. 在 `ivdata/providers/` 下新建类，继承 `Provider`，实现对应 `fetch_*`；
3. 在 `ivdata/providers/__init__.py` 的 `PROVIDERS` 里注册；
4. 加入 `ivdata/config.py` 的 `DOMAINS` 链——**先放第二位**，别直接取代主源；
5. 用 `tools/verify_sources.py` 对比一周，确认偏差在容差内；
6. 确认 `DOMAIN_SCHEMA` 的 `min_rows` / `fields` 能拦住残缺返回；
7. 把单位、限频、口径坑写进本文件。

## 一、取数层（run_daily.py 的 5 个同步步骤）

`run_daily.py` 依次执行 5 个同步步骤：**① 指数行情 → ② 指数估值 → ③ 期权 PCR →
④ ETF 份额与行情 → ⑤ 10Y 国债尾部补齐（非致命）**，
其后还有两个**补步骤（均非致命）**：指数收盘价历史增量（东财 K 线，`fetch_close_hist.py`）、
股指期货当月连续 + 中证1000 现货（新浪/东财，`fetch_futures.py`，v2.6.5 起）。

每个域的**优先级链、日常实际源、历史下界**，唯一权威表在
本文件**第一部分第一节「总览」**，此处不重复。
每次运行"实际用了哪个源"记录在 `work/provenance.json`（`provider` + `fallback_from` 字段）。

### 一、基本面：估值分析

**① 估值总表**（每指数一行）

| 列              | 字段                         | 出处                                                                   |
| -------------- | -------------------------- | -------------------------------------------------------------------- |
| 收盘/涨跌          | `close`, `ytd`, `m1`, `y1` | metrics.json（close 来自新浪日线；区间涨跌按日线算）                                  |
| PE-TTM/静态PE/PB | `pe_ttm`, `pe`, `pb`       | metrics.json ← 东财聚合（静态 PE 用 `PE_LAR`）                                |
| 10年分位          | `pe_pct`, `pb_pct`         | process.py 对 raw.json `basic` 全史计算                                   |
| 点位分位/点位中位数        | `close_pct`, `close_med`   | process.py 对 `data/close_history.json` 近10年日频收盘价计算（v2.6.3，与 PE/PB 分位同式；科创50 自 2020-07 上市起）。不进信号矩阵、不参与估值状态色标；表下小字展示沪深300/中证500/创业板指近十年点位中位数 |
| PE 区间统计        | `pe_min/med/max`           | 同上                                                                   |
| 总市值            | `mv`（万亿）                   | 东财 `TOTAL_MARKET_CAP`（单位=元，直存不换算）                                    |
| 隐含 ROE         | `roe`                      | = PB / PE(TTM)，process.py                                            |

**② PE/PB Band（估值带，v2.5.9 起取代旧"估值中枢迁移"月度折线）**

- Wind 式估值带：收盘价折线 + 窗口内 PE(TTM)/PB 的均值 ±1σ/±2σ × 当期
  EPS(TTM)（=收盘价/PE）/ BPS（=收盘价/PB），通道随盈利披露逐周倾斜。
- `gen2.py` 的 `band_data()`：每 ISO 周取最后一个交易日（周采样，10 年约 521 点/指数），
  注入 `DATA.band`（`{指数: {dates, close, pe, pb}}`）；
  统计与画线在前端完成。
- **收盘价**：`data/close_history.json`（2015~2019 段为一次性回填的历史段，
  其后东财 K 线增量；科创50 自 2020-07-24）。
- **交互**：默认沪深300 / 5 年窗口 / PE Band；指数（5 个）、窗口（3/5/10 年）、
  指标（PE/PB）三组按钮切换；窗口数据不足 80%（如科创50 × 10 年）自动回退
  "上市以来"并在图下注明。

**③ ERP（股债性价比）子章节** —— 交互式走势图 + 联动读数条（v2.6.1 起）

- `ERP = 100/PE(TTM) − 10Y 国债收益率`，`gen2.py` 内计算；
  10Y 序列来自 `data/yield10y_history.json`（东财 `RPTA_WEB_TREASURYYIELD`，
  数据源中国债券信息网/中债，2002-01-04 起日频）；
- **图与读数条共用一套状态（v2.6.1）**：`erp_weekly()` 注入 `DATA.erpS`
  （每 ISO 周取最后交易日，五指数各约 604 点），前端 `erpSlice()` 按所选
  **指数（5 个，默认沪深300）× 窗口（2015以来/10/5/3 年，默认 2015以来）**
  切片并计算均值 ±1σ/分位——图、读数条、"怎么看"说明三者同步切换；
  关键极值圆点（股灾前顶/2019底/疫情底/牛市顶/十年最高）仅沪深300 显示。
  y 轴自适应（创业板指/科创50 的 ERP 可为负）；
- **口径注意**：读数条是**所选窗口的周频口径**（与图一致），不再是固定
  "沪深300·2015以来日频"——±1σ 触发线随窗口变化，跨窗口比较不成立，
  报告图下说明已注明；v2.6.1 起 `DATA.erp`（日频统计块）已从 gen2 删除。
- **版式（v2.4.0 起）**：折线图上方不再放"当前读数表 + 怎么看"两栏卡片；
  图下方一张卡里是**横向读数条**（6 格，从左到右：当前 ERP / 历史分位 / 均值±1σ /
  +1σ 触发线 / −1σ 触发线 / 距 +1σ），再接一段合并后的说明
  （怎么看 + 触发条件 + 低利率口径提醒 + 样本区间与局限）。

### 三、情绪面：期权持仓 PCR

- **字段**：`pcr.{oi(当日), oi_pct(样本分位), oi_med/min/max/ma20/p25, vol(成交量PCR), n, start, series}`。
- **PCR 走势图**（v2.6.2 起）：窗口可切换（**全部 / 近三年 / 近一年，默认近一年**）。
  `gen2.py` 注入 `DATA.pcrAll`（pcr_raw.csv 每 2 日抽 1 点、锚定最新日，约 489 点，
  2022-10-10 起，以沪深300 标的日期对齐、缺日为 null，科创50 自 2023-06 由
  connectNulls 处理）。**表格与信号矩阵的 PCR 历史分位固定按全样本计算，不随窗口联动**
 （分位是信号输入，避免图表与表格口径打架）。
- **中间文件**：`work/pcr.json`（proc2.py），底层 `data/pcr_raw.csv`（逐日原始）+ `work/opts.json`（合约表）。
- **来源**：交易所官方期权日报
  - 上交所：`query.sse.com.cn COMMON_SSE_ZQPZ_YSP_QQ_SJTJ_MRTJ_CX`（需 Referer）；
  - 深交所：期权日统计接口（同 Host，注意限流）；
  - 回溯窗口：库里最后一天前 1 天 ~ asof（日常 1~2 发，覆盖缺日与定稿修正）。
- **口径**：PCR = 认沽持仓量 / 认购持仓量，按各指数**主要 ETF 期权**逐日汇总；  
  样本自 2022-10-10（科创50 自 2023-06-05）。
- **两市持仓量口径不同**（v2.5.0）：沪市 `LEAVES_*_QTY` 为双边加总；深市 `kzccsl`/`kdccsl` 为
  对冲后单边，**直接落库原值、不做换算**（与深交所页面逐位一致）。2026-09-09 起为单边、
  更早为双边口径，创业板指 PCR 历史分位跨该断点，页面已注明。
- **已知口径差**：到期日（周三）交易所报结算后持仓，与收盘持仓口径不同，  
  `KNOWN_OI_DIVERGENCE` 已在 `ivdata/providers/exchange.py` 记录离群日。

### 三、情绪面（续）：股指期货当月基差（v2.6.5）

- **字段**：`DATA.futAll`（`dates` YYMMDD 整数每 2 日抽 1 点锚定最新 + `series` 四品种
  基差率%，缺日 null）；`DATA.futTab`（读数表：`date` 读数日、`spot` 现货收盘、
  `rows[]` 全部存续合约——`label` 当月/次月/当季/下季、`code`、`fut`、`basis` 基差点数、
  `rate` 基差率%、`ann` 年化基差率（= rate × 365 / 距交割自然日）、`ddays`）。
- **基差率** =（期货收盘 / 现货收盘 − 1）× 100；负＝贴水、正＝升水。
- **当月连续拼接**（fetch_futures.py）：交易日 t 的当月合约 = t 所在月份合约，
  **晚于当月第三个周五（交割日）用次月**；由新浪各合约日 K 线拼接，
  逐位可复核（IF 2026-10-23=4080.2 与 IF2611 合约 K 线一致）。
- **存续合约（CUR）**：fetch_futures.py 同时落库当前挂牌的全部 4 只合约
  （当月/次月/随后两个季月，中金所规则）日收盘 → `futures_kline.json` 的 `CUR` 键，
  供读数表逐合约取值；到期日 = 合约月份的第三个周五。
- **现货**：沪深300/上证50/中证500 复用 `data/close_history.json`（与 Band 同源）；
  中证1000 为 `futures_kline.json` 内 `SPOT852`（东财 K 线为主，失败降级新浪 `sh000852`；
  2022-01 起）。
- **读数表数据（`CUR`）**：`CUR[品种][合约] = {date: close}`，四只存续合约分开存
  （v2.6.6 修正：此前误存为混在一起的 `{date: close}`，gen2 取值时报 AttributeError）。
- **期限标签（v2.6.7）**：`rows[].label` 前两只按位置＝当月／次月；第三、四只按**合约交割月**
  标「季月MM」（如季月03、季月06）。不用「当季/下季」——次月本身是季月时（如 2026-10 的
  2612）会错位。
- **历史下界**：IF/IH/IC 自 **2019-03**（新浪合约 K 线可查下界 2018-10，
  仅季月有更早数据）、IM 自 **2022-07-22**（上市日）。新浪 `IF0` 等连续代码是
  **主力连续**（按持仓量移仓），与当月连续口径不同，**未采用**。
- **判读**：贴水常反映对冲需求与谨慎情绪；5–7 月分红季贴水天然偏深（指数除息），
  宜与历史同期比较；深贴水亦含雪球等场外对冲盘卖出压力。期货收盘为新浪日 K 收盘，
  交割日当日仍用当月合约（收敛于现货）。近月临近交割基差收敛，**年化值波动大**。

### 机构展望（views）/ 综合解读（syn）

- 存放：`data/manual_inputs.json` 的 `views` / `syn`。
- **`views` 按机构组织，一行一家**：`{"org": 机构名, "date": 发布日, "scope": 覆盖标的, "view": 观点文本, "change": 变动要点（可选）}`。
  报告渲染成「机构 / 发布日 / **状态** / 核心观点 / **观点变化**」五列（v2.7.0 起），
  **按 `date` 从新到旧排列**：
  - 「状态」= **新增 / 更新 / 沿用**，由 `gen2.py` 把当前 `views` 与 `work/views_snapshot.json`
    的 `basis`（上一版报告的观点集）逐条比对自动判定，**不手填**；仅日期与正文都一致才算沿用。
  - 「观点变化」= 与同机构此前观点的差异要点：`basis` 里没有该机构 → "本期新收录"；
    有变动 → 取该条的 `change` 人工摘要，缺省则回退为"此前（旧日期）：旧观点前 110 字"；
    沿用 → 一律显示"与前版（日期）一致"，**故 `change` 只在观点变动那一版写一次即可**，
    次日状态转为沿用后自动隐去，不会变成过期文字。
  - 快照在报告成功落盘后写入：同日重复运行只刷新 `current`、不动 `basis`，
    因此当天改模板/排障重跑不会把"更新"抹成"沿用"；跨日首跑时 `basis := current`。
  - 2026-10-28 前的「覆盖标的」列（`scope` 仍在数据里，仅不再单独成列）与
    「对照读数」列（PE 分位/份额 60 日，脚本自动生成）已撤掉。
- **覆盖范围**：只收录**外资投行**（高盛、摩根士丹利、摩根大通、瑞银、野村、花旗、美银、德银等）
  对 **沪深300 / 创业板指 / A股整体** 的公开观点；不逐指数铺开，也不收内资券商。
- `syn[指数]` 是一句话结论，落在五、信号矩阵末列（目前只写沪深300、创业板指）。
- **生成方式**：每日流程在管线跑完后，**读 `work/metrics.json`、`pcr.json`、`shares.json` 据实撰写，
  回写 `manual_inputs.json`，再只重跑 `gen2.py`**（定时任务第 3 步）。
- `views` 为 `[]` 时表格显示"本期未收录外资投行观点"，不报错。
- **本文件不含任何数值指标**：行情、PE/PB、PCR、份额、10Y 全部由管线自动写入 `data/` 历史库。
- 股息率已于 v2.4.0 从报告移除（中证 `data-service/indexValuation` 只覆盖 8 只指数且有当日快照，
  创业板指/科创50 无来源），原因与接口明细见 DAILY.md 三（股息率段）。

## 四、怎么核对某个数字

1. **先看溯源**：`work/provenance.json` 里该域当次实际用的 provider；
2. **对中间文件**：按〇节速查表找到对应 work/*.json，确认报告值 == 中间值（排除 gen2 组装错误）；
3. **对原始源**：按本文件第一部分的接口重发一次请求比对；
4. **第三方官方对照基准**（2026-10-21 实测口径）：
   - 中证指数官网 `indexCsiDsPe`：仅 300/50 的静态 PE（字段名叫 peg），±3% 容差；
   - 国证官网 `GET www.cnindex.com.cn/index/indexList?channelCode=-1&rows=2000&pageNum=1`：  
     覆盖创业板指 399006 的 peStatic/peDynamic/pb **当日快照**。PB 与我们差 0.21%（一致✓）；  
     PE 低 ~15% 是编制方加权口径差（自由流通分级靠档 vs 我们总市值加权），**不可直接对比 PE**；  
     无历史序列，只能做当日校验。
