## [v2.7.6] — 2026-11-13

主题：**路径唯一化 + 依赖锁定**（消灭"换台机器才炸"的两类事故）。

### Added
- `ivdata/paths.py`：项目内路径的**唯一定义处**（`ROOT` / `BASE`（带尾斜杠）/ `DATA` /
  `WORK` / `REPORTS` / `SCRIPTS` / `ASSETS` / `p()` 拼接助手）。
- `scripts/_bootstrap.py`：把项目根加入 `sys.path`，让 `scripts/` 下的脚本
  在「run_daily 子进程调用」与「`cd scripts && python x.py`」两种方式下都能 `import ivdata`。
- `tests/test_paths.py`（5 例）：根目录名、尾斜杠语义、常用目录存在、无反斜杠混用、拼接助手。
- `.editorconfig`：统一缩进/换行/编码（只影响编辑器，不重写已有文件）。

### Changed
- `ivdata/config.py`、`scripts/{cfg,gen2,prep,proc2,tech}.py` 不再各自推导 `BASE`，
  全部改为 `from ivdata.paths import BASE`；`gen2.py` 读模板的路径改用 `paths.SCRIPTS`。
  顺带统一 `prep.py` 的 `BASE + "/data/…"`（其余文件都是 `BASE + "data/…"`）。
- `requirements.txt` 由下界（`>=`）改为精确版本：`requests==2.34.2` / `pandas==3.0.6` /
  `numpy==2.5.3`——本地与云端装同一版本，避免 pandas 3.x/2.x 的 dtype 与字符串语义差异
  造成「跑得通但数字不同」。

## [v2.6.6] — 2026-10-27

主题：**修复 06:00 定时任务失败三连**（死循环挂起 / CUR 结构错 / push2his 被拒）。

### Fixed
- **`fetch_futures.listed_contracts` 死循环**（本次"挂起 12 分钟"的真凶）：原来用
  `out[-1]` 当季月游标，当 out[-1] 是 12 月时下一个月是次年 1 月（非季月）不 append，
  游标不前进 → 无限空转、一行日志都不输出，进程被外壳杀掉，看起来像"网络挂起"。
  改为独立游标逐月推进 + `guard` 上限；实测 2026-10-27 → 2611/2612/2703/2706 正确。
- **`CUR` 数据结构错**：原用 `_merge` 把四个存续合约混成一个 `{date: close}` 扁平字典，
  `gen2` 取 `_fser.get(_fd)` 时 **`_fser` 是 float** → `AttributeError`，报告生成失败。
  改为 `CUR[prod][sym] = {date: close}`（按合约分开），并在 `_load` 后 `setdefault("CUR")`。
- **`push2his.eastmoney.com` 在本机被直接拒绝**（0.1s ProxyError，两个子域皆同；
  时好时坏，2026-10-27 06:00 表现为 `RemoteDisconnected`）：`fetch_close_hist.py`
  与 `fetch_futures.sync_spot852` 均改为 **东财为主、新浪指数日 K 降级**
  （`money.finance.sina.com.cn/.../CN_MarketData.getKLineData`，一次可取 5000 根）。
  降级时按 `HIST_FLOOR`(2015-01-05) / `SPOT_BEG`(2022-01-01) 截断，避免灌进 2006 年起的老数据。

### Changed
- **"非致命"清单写清楚，并要求标明滞后**（2026-10-27 用户定）：标 `[补]` 的三个步骤
  （10Y 国债 / close_hist / 股指期货）失败不停手、保留缓存照常出报告；但**严禁把旧数据
  当作当日值**——Band 卡在收盘价最后一日早于 asof 时显示「⚠ 收盘价数据截至 …（滞后）」，
  期货读数表在同样情形下显示「⚠ 滞后（报告日 …）」，总结里也要写明哪块滞后。
  提示词与 DAILY 同步（原来只声明了 10Y 一项）。
- `fetch_futures` 超时 20s → **8s**、新增**连续 3 次失败熔断**（`_try` + `_Breaker`）；
  `fetch_close_hist` 超时 40s → **10s**、连续 2 次失败终止。原因：25 个请求 × 20s 串行
  无熔断 = 最坏 8 分钟，一次网络抖动就能拖垮整条日报。
- **不改 `trust_env`（仍走 env 里的沙箱出口代理）**：实测置 `False` 后请求会卡在
  解析/连接层（超时参数管不到 DNS），2 分钟零输出——"直连"与"走代理"是同一出口路径，
  绕开代理没有任何收益。

## [v2.5.2] — 2026-10-21

主题：**行情真实性校验 + 定时任务提示词修订**（呼应"判重不该兼职判断交易日"的讨论）。

### Added
- `run_daily.py` 新增 `_verify_quotes(asof)`：取数后硬校验**五只指数 daily 里必须有
  `trade_date == asof` 的行**，缺任何一只立即停手、不出报告。
  动因：日历说交易日 ≠ 真的有交易（临时休市不在日历、数据源延迟），不校验就会把
  旧数据标成新日期。输出示例见 RUNBOOK 7.4。

### Changed
- 定时任务提示词（automation f3a34004）四处修订：
  1. 第 1 步 SKIP 措辞改准确："最近交易日的报告已定稿（可能因休市，也可能当天已处理过）"，
     不再说"无新增交易日数据"——SKIP ≠ 休市；
  2. 第 1 步注明 `--check` 句末"另有试运行文件…（不计入判重）"只是提示、不影响判定
     （配合 v2.5.1 的新输出）；
  3. 第 2 步锁定"正式文件名，不带 --tag 标记"，并写明行情校验拦截时按第 5 步停手；
  4. 第 3 步 views 的 `date` 明确格式 `YYYY-MM`（查得到精确日则 `YYYY-MM-DD`）。
- RUNBOOK 7.1/7.2/7.4 同步。

### 设计讨论结论
判重不负责判断交易日（交易日由交易所日历判断）；文件判重是**幂等保护**，
它优于纯日历判断之处在于"昨天失败、今天自动补跑"。保留 mtime>15:00 判据，
不为"收盘后取到旧数据"这种两年未出现的场景复杂化——真发生了由 `_verify_quotes` 拦住。

## [v2.5.1] — 2026-10-21

主题：**试运行报告加标记，避免让定时任务误判为「已跑过」而跳过**。

### Added
- `run_daily.py --tag NAME`（或环境变量 `IV_REPORT_TAG=NAME`）：报告存为
  `reports/index_val_report_<asof>_NAME.html`，例如 `--tag test`
  → `index_val_report_20261020_test.html`。标记会被规整为字母/数字/`-`/`_`，最长 16 字符。
- `scripts/cfg.py`：新增 `REPORT_TAG` 与 `report_path(asof, tag)`，`gen2.py` 改为调它生成输出路径
  （原来在 `gen2.py` 里硬编码文件名）。

### Changed
- `run_daily.py --check` 仍**只认无标记的正式文件名**；若同日存在试运行文件，
  输出末尾追加「另有试运行文件 …（不计入判重）」，判定结论不受影响。
- 启动横幅在带标记时打印 `试运行标记 = xxx（报告另存，不影响定时任务判重）`。

### 动因
盘后（15:00 之后）手工试运行会产出与正式文件同名的报告，`--check` 依据 mtime 会判定"已定稿"
→ 次日 06:00 的定时任务直接 `SKIP`，当天就没有定稿数据。加标记后两者互不干扰。

### 验证
- `IV_REPORT_TAG=test ASOF=20261020 python scripts/gen2.py` → 生成 `index_val_report_20261020_test.html`；
- `_report_state('20261020')` → `(False, '…数据已定稿；另有试运行文件 …_test.html（不计入判重）')`；
- 仅有试运行文件、无正式文件时 → `(True, '缺少 …的报告；另有试运行文件 …')`，即仍会 `RUN`。
